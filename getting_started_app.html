Getting Started with the App

The WWF ITR App is a Streamlit interface to the wwf-itr calculation engine. Use it to load data, calculate temperature scores, explore companies and scenarios, and download results without writing analysis code.

Try the online demo

Open the WWF ITR App in your browser. Choose Sample Data, click Load Data, and follow Using the App. No installation is required.

The public demo runs on Streamlit Community Cloud. Use sample or public data there; do not upload confidential or proprietary portfolio data. For your own confidential data, run the app locally using Docker or Python. Use a separate installation and data directory for each user. The app does not provide user accounts or dataset permissions for a shared installation. Cloud storage is temporary across app restarts; download any results you want to keep.

Run locally with Docker

Docker runs the same Streamlit app on your own computer. You do not need to install Python or clone either GitHub repository.

  1. Install and start Docker. See the official instructions for Windows, macOS, or Linux. Docker Desktop includes Compose; on Linux, also install the Compose plugin.

  2. Create a folder for the app, for example wwf-itr-app. Download docker-compose.yml into that folder. The file contains:

    services:
  itr:
    image: ghcr.io/wwf-sweden/wwf-itr-app:latest
    ports:
      - "127.0.0.1:8501:8501"
    volumes:
      - ./data:/app/data

  3. Open a terminal in that folder and start the app:

    docker compose up -d --pull always

  4. Open http://localhost:8501 and follow Using the App.

The port is bound to 127.0.0.1 for access from your own computer, rather than through its LAN or Wi-Fi address. Use Docker Engine 28.0.0 or later: older versions have a known issue that can allow other devices on the same network segment to reach ports published to localhost. See Docker’s port publishing documentation.

The first start downloads the image from GitHub Container Registry. Example data may also be downloaded from GitHub when not already present. SBTi data is downloaded when required unless you select an uploaded CTA file or use the app’s offline option with available local data.

Stop, restart and update

Run these commands from the folder containing docker-compose.yml. To stop the app and remove its container:

docker compose down

To start it again and check for a newer published image:

docker compose up -d --pull always

To inspect its status and logs:

docker compose ps
docker compose logs -f itr

Press Ctrl+C to stop following the logs. latest follows the latest published app image. For a reproducible installation, use an existing release tag or image digest from the container registry and record it with the analysis. App image tags and Python package versions are separate version identifiers.

Keep your saved data

The volume ./data:/app/data keeps saved application data in the data folder beside your Compose file:

  • data/itr_data.db contains datasets explicitly saved using Save.

  • data/cta/current-Companies-Taking-Action.xlsx is the app’s CTA cache.

These files survive docker compose down and image updates. Back up the folder before updating and keep it if you want to retain saved datasets. Loading or editing a dataset does not automatically save it to the database. Temporary uploads are not all retained by the volume. Downloaded exports are saved through your browser, normally to your Downloads folder.

Loaded data and session lifetime

The app reads provider uploads, portfolios and pre-scored files in memory without creating application-managed temporary disk copies. Provider uploads read only the required fundamental_data and target_data sheets. The app does not store analysis data or results in global Streamlit caches; loaded data and reusable results belong to the current browser session. Repeated what-if scenarios can reuse up to three results within that session, with a total budget of 32 MiB of serialized result data. This budget does not limit the app’s total memory use. Provider data, the portfolio, scenario settings and CTA contents are included in the cache key. Least recently used results are evicted; oversized results are calculated without caching. This cache remains in memory and is cleared with the loaded data. Streamlit usage statistics are disabled in the supplied app configuration.

Use Clear loaded data / Change source to release the session’s loaded data, results and uploads. This keeps explicitly saved SQLite datasets and browser downloads. It does not securely erase process memory. Closing a tab does not guarantee immediate session disposal; stop the app or container to end the running process.

Custom CTA uploads still need a temporary file. Their session-owned directory is removed when the upload is replaced, removed or cleared, or when the session owner is normally released. Abrupt process termination can leave temporary files behind. Updating does not remove files left by older versions. Device access, disk encryption, backups and operating-system swap remain the user’s or organization’s responsibility.

These changes require the updated app version. Updating this documentation or the calculation package alone does not update an installed app/container.

Run locally with Python and Streamlit

This alternative is useful if you want to work with the app’s source code. Use Python 3.11, the version used by the app’s Dockerfile and test workflow, and Git. Clone the app repository:

git clone https://github.com/WWF-Sweden/WWF-ITR-APP.git
cd WWF-ITR-APP

Create and activate a virtual environment. On macOS or Linux:

python3.11 -m venv .venv
source .venv/bin/activate

On Windows PowerShell:

py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1

Then, from the app repository root:

python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address=127.0.0.1

Open http://localhost:8501. Stop the server with Ctrl+C. The app’s pinned requirements install its wwf-itr dependency. Installing wwf-itr alone does not install the Streamlit app.

For input files and the first analysis, continue with Using the App. If startup fails, see Troubleshooting.
